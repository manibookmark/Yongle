# CJK AI Font Design (`cjk-ai-font-design`)

A battle-tested, cross-agent workflow for designing original brush, calligraphic, or stylized CJK fonts with AI image generation and Python font engineering. Distilled from the open-source **Yongle (永乐)** 3,500-character Ming-era *Yongle Dadian* Taige-ti Simplified Chinese font project.

## Core Design Principles (Learned the Hard Way)

1. **Always generate full 4×4 (16-glyph) boards — never isolated 1–6 glyph sheets.**
   Generating only a few characters on a canvas changes visual scale and stroke weight relative to full sheets. Even when repairing 5–6 defective glyphs, pad the remaining slots of the 4×4 board with master-style companion glyphs and skip those companions during tracing.
2. **Interleave sparse and dense characters on every 4×4 sheet.**
   A sheet filled exclusively with low-stroke characters (`一、二、三、上、下、土、王、水`) causes image models to lose brush rhythm and drift into generic digital KaiTi/FangSong. Pair 8 medium/dense characters with 8 sparse characters per sheet (2+2 per row).
3. **Never ask an image model only to "make strokes thinner."**
   Pure "thinning" prompts strip away calligraphic tilt (`扛肩`), shoulder pressure (`折肩顿笔`), and flaring endings (`撇捺`), collapsing a custom typeface into standard computer KaiTi. Anchor prompts to the exact brush modulation and weight of a locked 16-glyph **Master Board** (`master_16.png`).
4. **Vectorize with proportional `keep_sheet_scale`, not independent per-glyph box stretching.**
   Stretching every glyph independently to fill the same 875×814 bounding box destroys optical proportions (e.g., making `一`, `二`, `小`, `口` gigantic). Compute one uniform sheet scale per 4×4 board from the sheet's median glyph size so natural size hierarchy survives into the TTF.
5. **Never rely on single-sheet eyeball inspection alone — audit against a standard reference font.**
   AI image models routinely drop a single dot (`孵→卯+孚`, `搀→挽`), drop an inner bar (`禀` missing inner `口`, `算` missing a bar in `目`), or swap lookalike radicals (`粱→梁`, `赣` misplacing `攵`/`贝`). Run `scripts/audit_glyphs.py` to compare every generated glyph against a standard reference font (`simkai.ttf`, Noto Serif CJK, etc.) by **enclosed hole count + dilated ink mismatch** and review the side-by-side contact sheets.
6. **Use Dual-Reference Repair for stubborn/complex glyphs.**
   When repairing defective glyphs, pass **two images** to the image generator:
   - Image 1: Your locked **16-glyph Style Master** (sole source of brushwork & weight).
   - Image 2: A **Standard Structure Strip** auto-generated by `scripts/audit_glyphs.py --make-structure-ref` (sole source of GB2312/Unicode stroke structure).
   This eliminates prompt-description ambiguity and achieves near-100% first-try accuracy on complex characters (`凿、孵、姊、兜、赣、禀、矗、躏`).
7. **Freeze baselines and merge strictly via an explicit approval whitelist.**
   Never auto-glob all batch folders during a release build. Maintain `approved_batches.json` listing rejected experimental batches, approved batches, and targeted override batches.
8. **Harmonize companion English letters, digits, and punctuation with the final Hanzi weight.**
   Whenever Hanzi stroke weight is refined, re-check mixed Chinese + English + digit + punctuation rendering (`24px`, `32px`, `48px`). Keep digits upright (not slanted), align ASCII/punctuation stem weight and optical width with the Hanzi main stem, ensure fullwidth em-dashes (`——`) connect seamlessly, and include Chinese curly quotes (`“”‘’`).

## Quick Setup (Auto-Run on First Use)

Before running any pipeline script, verify (and if missing, auto-install) Python dependencies in one command — no manual setup required from the user:

```bash
python scripts/setup_env.py --install
```

Any image-generation capability available in your agent environment works (Codex built-in `image_gen`, OpenAI GPT Image, Gemini image generation, or local diffusion workflows supporting reference-guided editing).

## 6-Stage Workflow

### Stage 1: Define Style & Lock the 16-Glyph Master Board
1. Agree on target script (Simplified/Traditional), usage (display headline vs. horizontal/vertical body text), and initial repertoire size (start with a 100–300 glyph MVP before scaling to 3,500 GB/Common-1 Hanzi).
2. Curate 16 representative control glyphs covering sparse, dense, enclosed, left-right, and top-bottom structures (for example: `人膏日旧 / 羽目肇大 / 同哥十誓 / 骨小国警`).
3. Generate candidate 4×4 black-on-white square boards (no grid lines, no watermarks, no captions) using the Master prompt in `references/prompt-templates.md`.
4. Vectorize the chosen master with `scripts/trace_batch.py`, preview it in real horizontal/vertical sentences via `templates/specimen.html`, and **freeze** `master_16.png` once the user approves its brushwork and weight.

### Stage 2: Plan Density-Balanced 16-Glyph Batches
Use `scripts/plan_batches.py` to split your target character list into 4×4 batches with balanced stroke density (and automatically exclude already-approved glyphs):

```bash
python scripts/plan_batches.py \
  --repertoire repertoire.txt \
  --ref-font /path/to/standard-reference.ttf \
  --exclude-json approved_batches.json \
  --start-batch 1 \
  --out batch_plan.json
```

### Stage 3: Generate 16-Glyph Boards & Eyeball-Screen Each Sheet
1. For each batch in `batch_plan.json`, generate a 1:1 pure-white, pure-black 4×4 image referencing `master_16.png` using the batch prompt in `references/prompt-templates.md`.
2. Inspect every generated sheet immediately:
   - Check stroke completeness, simplified/traditional standard correctness, and brush consistency with `master_16.png`.
   - Record any defective characters in the batch's `skip` string so they are **never vectorized into the font**, and queue them for Stage 5 repair.

### Stage 4: Vectorize Each Batch into TTF / WOFF2 + Preview
Run `scripts/trace_batch.py` to slice cells by whitespace projection, vectorize with `vtracer`, scale uniformly (`--keep-sheet-scale`), convert cubic splines to TrueType quadratics (`Cu2QuPen`), and emit a verifiable single-batch TTF, WOFF2, and HTML proof:

```bash
python scripts/trace_batch.py \
  --image batches/batch001/sheet.png \
  --rows "家步行水,复天于而,片下从不,之君其直" \
  --skip "直" \
  --baseline base/SeedFont.ttf \
  --out-dir batches/batch001 \
  --family MyFont-Batch001 \
  --keep-sheet-scale
```

### Stage 5: Automated Typo & Weight Audit + Dual-Reference Repair
After completing a wave of batches, run `scripts/audit_glyphs.py` against a standard reference font (e.g. `simkai.ttf` on Windows or Noto Serif/Sans CJK):

```bash
python scripts/audit_glyphs.py \
  --font release/MyFont-Candidate.ttf \
  --ref-font C:/Windows/Fonts/simkai.ttf \
  --chars-file wave_chars.txt \
  --out-dir qa/audit
```

Review the generated `suspect_page_*.png` side-by-side contact sheets (`[Standard Gray | Candidate Black]`, annotated with enclosed hole counts `h:cand/ref`). For any defective characters discovered:
1. Generate a crisp standard-font structure strip:
   ```bash
   python scripts/audit_glyphs.py \
     --make-structure-ref "凿孵姊兜壁匆" \
     --ref-font C:/Windows/Fonts/simkai.ttf \
     --out-dir qa/repair
   ```
2. Pad the defective characters to a full 16-glyph 4×4 grid using master companion glyphs (placed in `--skip` during tracing).
3. Regenerate with **both** `master_16.png` (style/weight) and `structure_ref.png` (stroke structure) attached, trace only the repaired characters, and register the repair batch under `override_batches` in `approved_batches.json`.

### Stage 6: Whitelist-Protected Release Merge & Full Verification
Merge only explicitly approved batches onto the frozen baseline and verify every single codepoint:

```bash
python scripts/merge_release.py \
  --baseline base/FrozenBaseline.ttf \
  --approval approved_batches.json \
  --out-dir release \
  --family MyFont-SCCommon
```

`merge_release.py` enforces:
- Exact `cmap` match between baseline, output TTF, and output WOFF2.
- Bit-exact outline and `advanceWidth` parity between TTF and WOFF2.
- Non-empty raster rendering for every Hanzi at `24px`, `48px`, and `96px`.
- Interactive before/after horizontal & vertical HTML comparison page.

## Compliance & Licensing Rules

- **Never trace, extract outlines from, or feed commercial fonts as style references.** Use public-domain historical manuscripts, original hand-lettering, or permissively licensed open-source works (respecting SIL OFL 1.1 Reserved Font Name rules).
- Keep the Skill/tooling license (MIT) separate from your generated font's license (recommended: **SIL Open Font License 1.1**).
